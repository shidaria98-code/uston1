## Совместимость сохранений

- Схема экспортного файла остаётся `udm-space-save`, version 1.
- Ключи не переименованы. Новая версия читает старые сохранения.
- Для первой главы объединяются `multan-answers-1` и `multan-chapter1-answers`. При конфликте одного ответа приоритет у `multan-chapter1-answers`: прежняя версия записывала ответы первой главы именно туда. После чтения и при ответе/повторном ответе оба ключа синхронизируются. Уникальные ответы из второго ключа сохраняются.
- Значение `null` не записывается строкой как отсутствующая позиция. Старое строковое `null` у позиции главы удаляется при чтении; неверные, бесконечные и выходящие за пределы позиции безопасно приводятся к допустимой сцене.
- При запуске приоритет имеет отдельная сохранённая позиция первой главы; старый ключ используется как резервный. Позиция первой главы больше не переписывается сценами других глав в её старом ключе.
- При ошибке импорта восстанавливаются исходные строки всех затронутых ключей, включая отсутствие ключа. При невозможности полного восстановления выводится отдельное сообщение; исходный файл нужно сохранить.
- При недоступном Storage новелла продолжает работу с данными в памяти. Они действуют до закрытия/перезагрузки страницы; это не постоянное сохранение.

## Оставшиеся ограничения

- localStorage не предоставляет настоящую транзакцию. Откат защищает от проверенного отказа записи в работающей вкладке, но не гарантирует атомарность при аварийном завершении браузера/ОС или одновременной записи из другой вкладки. При запрете самим браузером любых операций откат тоже может быть невозможен; это явно сообщается.
- При file:// origin непрозрачен. Если браузер запрещает проверить локального родителя, обмен сохранениями через postMessage отключается; игры и возврат продолжают работать, собственное сохранение зависит от политики браузера. Для полноценного общего профиля и переноса данных следует проверять полную папку через локальный HTTP-сервер либо GitHub Pages. Нельзя безопасно доверять любому origin `null` ради переноса данных.
- Блокировка чужого встраивания выполняется в JavaScript, не HTTP-заголовком. На будущем сервере нужен CSP frame-ancestors 'self'; meta CSP не заменяет этот заголовок. Перед реальной авторизацией необходим отдельный серверный аудит.
- Локальные очки по-прежнему могут быть изменены владельцем браузера. Серверной верификации, аккаунтов и приватного портфолио этот патч не добавляет.
- Smoke-проверки 12 модулей не равны полному прохождению всех веток и уровней каждой игры. Реальные Safari/iOS/Android, экспертная языковая проверка и все замечания аудита вне A01–A05/A10 остаются за рамками патча.

## Проверка и публикация

До отдельного подтверждения владельца не сливать PR, не менять источник Pages и не публиковать ветку.

1. Сохранить экспорт текущего профиля через существующую кнопку. Не очищать данные сайта.
2. Открыть полную папку сборки через `python3 -m http.server 8771` и перейти на http://127.0.0.1:8771/. Данные другого origin автоматически не переносятся: для отдельного теста использовать копию экспортного JSON. Рабочую вкладку оставить нетронутой.
3. Проверить три главы новеллы, ответ и I → II → I; сохранённое выполненное задание самоучителя; экспорт/импорт копии профиля; запуск нужных игр. Все ресурсы должны оставаться в полной папке.
4. Для повторения автоматических проверок установить Node.js и Python 3; в отдельной рабочей копии выполнить `npm install --no-save --package-lock=false playwright@1.58.2`, `npx playwright install --with-deps chromium`, запустить HTTP-сервер из корня копии (`python3 -m http.server 8771`), затем `CHROMIUM_PATH="$(node -e 'process.stdout.write(require("playwright").chromium.executablePath())')" node tests/mvp-regression.cjs`. Тест сам временно поднимает второй локальный сервер на порту 8772. CI делает это автоматически на Ubuntu 24.04. Эти зависимости нужны только тестам.
5. После подтверждения владельца проверить, что main не изменился относительно основы; при изменениях сначала обновить ветку и повторить тесты. Затем слить PR (предпочтительно одним squash-коммитом) и дождаться успешной существующей публикации Pages. Сам патч не меняет конфигурацию Pages.
6. Открыть прежнюю опубликованную ссылку в том же браузере; проверить существующий профиль и исправленные сценарии. Не менять домен/протокол и не сбрасывать localStorage.
7. Для отката выполнить отдельный revert коммитов приложения с сохранением истории, затем повторить Pages-публикацию. Данные браузера не удалять. Старый экспорт оставить резервной копией.
