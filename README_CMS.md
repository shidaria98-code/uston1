# Редактирование портала через Pages CMS

Подготовлена адаптация шести разделов портала «Усьтон». После однократной загрузки файлов и настройки публикации тексты можно изменять через формы Pages CMS. Каждый раз вручную загружать архив сайта не потребуется.

## Однократная настройка через сайт GitHub

1. Распакуйте архив адаптации. Откройте `shidaria98-code/uston1`, ветку `main`, корень репозитория.
2. Через **Add file → Upload files** загрузите содержимое архива с сохранением папок. На Mac сочетание **⌘⇧.** показывает скрытые файлы: в пакете есть `.pages.yml`, `.github`, `.gitignore` и `.nojekyll`. Внешнюю папку архива не добавляйте перед путями.
3. Если браузер не позволяет перенести скрытые файлы, загрузите видимые папки и файлы, а затем выполните два действия:
   - Откройте вашу страницу **Pages CMS → Configuration**. Вставьте туда весь текст из отдельного файла `Pages-CMS-configuration.yml` и нажмите **Save**. Сервис сохранит его как `.pages.yml` в корне репозитория.
   - В GitHub выберите **Add file → Create new file**. В имени файла укажите `.github/workflows/pages-content.yml`, вставьте весь текст из отдельного файла `GitHub-Pages-publication.yml` и сохраните изменение. Если файл уже существует, откройте его и используйте кнопку редактирования.
4. В GitHub откройте **Settings → Pages → Build and deployment → Source**. Выберите **GitHub Actions**. Это обязательный шаг: редактируемые материалы должны проходить автоматическую сборку перед публикацией.
5. Откройте вкладку **Actions**, выберите **Publish portal content**. Если первая попытка произошла до переключения источника публикации, запустите её заново через **Run workflow** для ветки `main`.
6. Дождитесь зелёного результата. Обновите страницу Pages CMS. В меню появятся шесть разделов, перечисленных ниже.

Не требуется загружать оба архива. Архив адаптации применяется к уже существующему репозиторию; полный архив предназначен для хранения и отдельного просмотра.

## Что можно редактировать

| Раздел Pages CMS | Поля |
| --- | --- |
| Мы сеем | Название, подзаголовок, названия категорий, 50 слов и переводов, подсказки, справки, замена изображения |
| Кин та? | Подзаголовок, шесть описаний, имена персонажей, замена портретов и аудио |
| Кытын? Кытчы? Кытысь? | Десять начальных форм и переводов, формы для трёх вопросов, русские и удмуртские предложения, свои объяснения |
| Семья | Имена, возраст и описания персонажей, 20 историй на двух языках, подписи родственников |
| Открываем Удмуртию | Тексты 25 районов, источники и дата сверки |
| Методическая основа | Заголовки, абзацы, карточки, библиография и ссылки |

Служебные номера скрыты и защищены. Их проверяет также сборка сайта. Порядок элементов в редакторе не меняет номера заданий и сохранённый прогресс. Число категорий, игровых слов, эпизодов, районов и семейные связи остаются прежними; создание новых типов заданий требует отдельной доработки игры.

## Обычная работа после настройки

1. Откройте https://app.pagescms.org/shidaria98-code/uston1/main.
2. Выберите раздел и разверните нужную карточку.
3. Измените поля и нажмите **Save**.
4. GitHub автоматически проверит материалы, соберёт и опубликует сайт. Обновление появится после завершения **Publish portal content** во вкладке **Actions**.
5. Обновите страницу портала. При необходимости используйте **⌘⇧R**, чтобы браузер перечитал файлы.

В форме вводится обычный текст, без HTML. Для абзацев методической страницы есть отдельные поля; в текстах районов абзацы можно разделять пустой строкой.

## Особенности заданий

**Мы сеем.** В удмуртском слове допустимы только буквы игровой клавиатуры. Пустая подсказка означает обычный русский перевод. Справка не уменьшает баллы. Пустое поле изображения возвращает исходную иллюстрацию.

**Кин та?** После изменения смысла описания проверьте соответствие озвучки и при необходимости загрузите новую запись. Если изменить имя на заставке без новой записи имени, прежняя запись не будет выдаваться за новое имя. Карточки и правильные ответы остаются связаны с исходными эпизодами.

**Кытын? Кытчы? Кытысь?** Укажите начальную форму, правильную форму и предложение отдельно. Правильная форма должна встретиться в удмуртском предложении ровно один раз. Для «сюрес» и «пужым» сохраняется модель с отдельным послелогом. В личный словарь передаётся начальная форма из поля, а не слово с отсечённым окончанием. Словарь обновляется вместе с материалами, без ручной правки его программного файла.

**Районы.** Ссылки `[1]`, `[2]` в тексте соответствуют порядку источников в карточке. При изменении списка проверьте нумерацию. Названия районов защищены, чтобы карточки не оторвались от карты.

**Изображения и аудио.** Новые файлы загружаются через поля CMS в папку `media`. Путь публикации настроен для текущего адреса `https://shidaria98-code.github.io/uston1/`.

## Если проверка не прошла

Последняя успешно опубликованная версия остаётся доступной. Откройте **Actions → Publish portal content → Validate and compile editable materials**: сообщение укажет поле или задание, которое требует исправления. Исправьте его в CMS и сохраните ещё раз. Например, сборка остановится, если форма слова отсутствует в предложении или удалён служебный номер задания.

## Что остаётся неизменным

Сохранены ключи прогресса, номера заданий, начисление баллов, семейная схема, случайный порядок заданий и действующее оформление. Данные игроков продолжают храниться в браузере; CMS управляет материалами сайта, а не профилями игроков.

## Техническая справка

Редактируемый источник — шесть файлов в `content/`. Файл `.pages.yml` описывает формы. `tools/build_content.py` проверяет данные и обновляет существующие статические программы и общий лексикон. Публикуется папка `_site`, в которую попадают только файлы сайта и медиа; инструменты сборки и проверки в публикацию не копируются.

Локальные команды для разработчика:

```sh
python3 tools/build_content.py --check
python3 -m unittest discover -s tests -p 'test_cms*.py'
python3 tools/build_content.py --publish
node tests/cms-content.cjs
node tests/november-content.cjs
```

Сборка использует стандартную библиотеку Python и Node.js. Дополнительная база данных и отдельный сервер CMS не требуются. Настройка выполнена по официальной документации: https://pagescms.org/docs/configuration/.

**Ческыт.** Словарь магазина редактируется в коллекции «Ческыт · словарь». Сборка обновляет игру и каталог общего словаря из этих же данных. Игрок видит слова и числительные в общем словаре по мере появления в игре.
